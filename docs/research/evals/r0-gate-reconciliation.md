# R0: reconciliation of R1 to R6 at the research gate

Read this first. The orchestrator wrote it after reading all six research notes at the Phase 1 gate. It settles every contradiction between them that evidence can settle, and hands every other one to the spec agents as a numbered open decision. Where this note and an R-note disagree, this note wins, because it was written with all six in view.

## Settled by evidence

1. **The failure ladder is R1's ten rungs.** R4 §6 and the brief use a six-rung list. It maps onto R1 as follows: "never emitted" is rungs 1 and 2, "not reached" is rungs 3 to 5, "unparsed" is rung 6, "rejected as prompt injection" is rung 7, "parsed but ignored" is rung 8, and "partially acted on" is rung 9. Rung 10 (acted on, then destroyed or misplaced) has no counterpart in R4. Specs use R1's numbering.
2. **Claude Code reads `AGENTS.md` natively.** R4 §3 item 5 says it discovers only `CLAUDE.md`. R3 measured the opposite on Claude Code 2.1.285: a root holding only `AGENTS.md` delivered its codeword. R3 also measured that a `CLAUDE.md` in the same directory shadows `AGENTS.md` completely. A minted root therefore holds `AGENTS.md` and no `CLAUDE.md`, or `CLAUDE.md` as a symlink to it. R4's per-provider `discovery` field is unnecessary for these two Host harnesses.
3. **Antigravity runs headless.** R4 §9 lists it as unmeasured. R3 measured `/opt/homebrew/bin/agy -p --output-format stream-json`, native `AGENTS.md` discovery, and a parent-directory walk. Its hooks remain unprobed, it has no turn cap, and it has no isolation flag.
4. **Word commands, not flags.** #222, R4 and the brief write `mh --query` and `mh --check`. The repository dogfoods 0.0.6 since `fc96e7b`, and the CLI takes `mh query <path>`, `mh check`, `mh assess <path> [--now <iso>]`. Specs use the word forms.
5. **The push surface is not a product feature.** R4 §4 describes a "PreToolUse `--query` hook" as if it ships. R1 established from code that `query-hook.mjs` is wired nowhere, handles only `Write` of a new `.md` file under body-structure, and writes no activity-log row. The AGENTS.md pull line is not shipped either. Both delivery surfaces are things the eval must construct as arms.
6. **Exit code 0 means nothing about a session.** R3 measured both Host harnesses exiting 0 on an authentication failure, and `agy` exiting 0 on a denied write. Failure classification must read stream fields (`is_error`, `terminal_reason`, `result.status`, stderr), never the process exit code. This sharpens R4 §7.4 rather than contradicting it.
7. **Headless runs survive #18's objection.** Map #18 chose manual interactive runs because a manipulation check needs a transcript (R6 A2 item 15). R3 measured that `--output-format stream-json --verbose --include-hook-events` yields tool calls, tool results and `hook_started`/`hook_response` events in a headless Claude Code run. The manipulation check therefore survives headless for Claude Code. For `agy` it survives for pull (tool calls are in the stream) and is unproven for push.
8. **Mint outside the repository, by copy.** R3 measured that both Host harnesses walk parent directories for instruction files, so a root under the checkout or `.worktrees/` inherits this repository's `AGENTS.md`. R6 contradiction 12 adds that #222's symlinked build lets the agent follow the link back into held-out material. Roots are minted under `/private/tmp/...`, with a parent-chain assertion at mint time, and the build is copied, never linked. `setup-local-e2e-repo/scripts/new-repo.mjs --under` is the existing seam to prefer.
9. **Isolation flags for Claude Code are known.** `--setting-sources project --strict-mcp-config --disable-slash-commands` took skills and MCP servers to zero and kept subscription auth (R3). `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, an allow-list environment (which drops `ANTHROPIC_BASE_URL` and the parent session's `CLAUDE_CODE_*` variables), and an assertion on the init event (`apiKeySource: "none"`, empty `skills` and `mcp_servers`) complete it.

## Contradictions handed to the spec agents

Each spec must state its answer to every item below, by number.

- **D1. Where impure code may live.** R4 proposes five `.impure.ts` files inside an eval Package. R6 shows that ARCH-008 §2.1 (an Archgate ADR) allows only `foundation` to import a platform builtin, enforced by `only-the-gate-imports-a-builtin` in `.dependency-cruiser.cjs`. A Package therefore cannot spawn a Host harness, call `fetch`, make a temporary directory, or write a report. The compliant options are pure logic in a Package with the impure shell outside `src/`, or impure scripts outside `src/` only. Amending ARCH-008 needs Han's approval and `archgate:adr-author`; no spec may assume that approval.
- **D2. Is a missing delivery an instrument failure or a result?** R6 decision 4 says a delivery that did not happen must be an instrument failure. R1 rung 3 treats "the agent never called `mh query`" and "the agent created the file through `Bash`, so the `Write` hook never fired" as measured outcomes. The orchestrator's reading, offered rather than imposed: a failed canary (the hook cannot fire at all in this Host harness and root) is an instrument failure for the whole cohort, while a hook that could fire but did not, because of the agent's own choices, is a rung-3 outcome. Specs must state the rule and how the canary distinguishes the two cases.
- **D3. The `.env`-keyed endpoint provider.** R6 B1 rules that the text of `docs/vision/product.md:122` (a vision doc) permits a key held by repository tooling, provided the code is absent from `dist/`, unreachable from `cli.ts`, and outside the gate. The reading needs a human sentence in a design-ADR before it is relied on. Han has not given that sentence. Specs may phase the endpoint provider but must gate that phase on the design-ADR, and no first phase may depend on it. R4 recommends single-shot Mode A before the stand-in tool loop, Mode B.
- **D4. Trials per arm.** #222 proposes three trials and a two-of-three threshold. R5 shows by the rule of three that 0 of 3 bounds the neutral arm's marker rate at about 100%. R6 decision 13 records that no variance has ever been measured. Specs must state a budget, derive a trial count from it, and say how the marker's base rate is bounded (the neutral arm alone, or R5's pre-screen plus the neutral arm).
- **D5. Where marker strings live.** R5 wants markers out of committed text, because the repository is public and a committed marker is burned. #222 decision 3 keeps held-out `cases/` committed beside each suite. Markers are never minted into a root in either design, so the transcription guard holds either way. The open question is whether markers are committed (reproducible, burnable) or generated per run from a recorded seed (fresh, reproducible only by seed).
- **D6. What a steer case grades given push timing.** #221 argued, without measuring, that a `PreToolUse` `Write` hook arrives after the first draft is composed. R1 rung 4 and R6 row 18 make this the meaning of "steered". Specs must say whether the graded artefact is the final file, the union of writes (R1 rung 10), or both, and whether a file created through `Bash` counts.
- **D7. Hook ownership.** Making push observable at rung 3 needs either an activity-log row in `query-hook.mjs` (a product skill edit) or an observer hook passed outside the minted root (R1, after `prepare-ablation-run`'s `observe-hook.sh`). R3 shows that Claude Code's `hook_started` event already proves a hook fired headless. Specs choose; editing product skill scripts is in scope only if the spec phases it explicitly.
- **D8. The carrier walk across two Modules.** Deriving the intent-neutralised arm means replacing every `intent` carrier, and the carriers sit in shapes that two Modules own. ARCH-008 §1.1 and §1.4 forbid an eval Package from naming a Module's section types (R6 contradiction 7). Specs choose between a generic YAML-document walk and a carrier list each Module publishes. The second option touches product code.
- **D9. The tool question.** R2 found that `promptfoo` exits non-zero on failed assertions by default, which breaks the exit contract unless overridden or wrapped. It also caches by default, which replays sessions unless switched off. `evalite` needed a `better-sqlite3` override to install on Node 26, and exited 0 at a 50% score. `deepeval` adds Python. Specs that adopt a tool must say how each of these is neutralised and prove it by breaking it.
- **D10. The assess surface.** `assess-hook.mjs:191` forwards no `--now`. A level-one eval may leave `assess.stale` to a later phase. If it does not, it chooses between a skill edit and a far-past `stale_after` seed (R6 B6).

## Vocabulary for both specs

Use these, and list every new term in the spec's Further Notes for a later domain-modelling pass. Neither spec edits `CONTEXT.md`.

- **Steering content** is what `mh query` returns, and what reaches the agent. Do not write "signal": `CONTEXT.md` defines Signal as a document's statement about its own trustworthiness.
- Qualify **marker** as **steering marker**, because `CONTEXT.md` and ARCH-002 already use "marker" for the Conformance `<!-- expect: -->` comment.
- **Suite** and **arm** collide. `CONTEXT.md` forbids "suite" for a per-tier unit, and `arm` was a glossary term retired with the ablation study. Use them only qualified (**eval suite**, **intent-neutralised arm**), and flag both.
- **Host harness** is always qualified. Bare "harness" is never used. A bare-endpoint tool loop is a **stand-in host** and never a Host harness.
- Other new terms the R-notes flagged: intent carrier, intent address, failure rung, cohort row, minted root, trial, canary, delivery channel, instrument failure, graded failure.
