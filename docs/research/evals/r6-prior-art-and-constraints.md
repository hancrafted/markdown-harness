# Part A: prior art

## A1. What #222 already decided (the nearest prior spec)

#222 is a prototype spec filed 2026-10-04 on branch `prototype/eval-suite` and never merged. It is the closest thing to a design for this eval, and the brief inherits most of it. Its decisions that matter here, with their numbers in the issue body:

- Decision 1: one oracle. The eval consumes `mh check`, `mh query` and `mh assess` from the compiled entry and never re-derives a verdict.
- Decisions 2 and 3: a suite is a synthetic repo root under `fixtures/evals/<suite>/`; a `cases/` directory beside it is held out and never minted into a run.
- Decision 4: three case kinds, one per surface an `intent` reaches (steer, repair, assess).
- Decision 5: two arms, `as-written` and `intent-neutralised`, where the neutralising function replaces every `intent` carrier with a constant filler (mandatory carriers cannot be removed because `CONFIG_EMPTY_INTENT` and `CONFIG_MISSING_*_INTENT` refuse the config).
- Decision 6: rubric anchors with two-way closure, computed by evaluating the loaded config and never by grepping (verification trap 4).
- Decision 8: the transcription guard is deterministic: the task text may contain no `pattern` source, no `fileNames` token, no heading literal and no `intent` text.
- Decision 9: hook proof is deterministic and per case (trap 10).
- Decision 10: two impure seams, `runContributorSession` and `judge`, with everything above them pure.
- Decision 12: classification of an arm pair as `working`, `inert`, `wording` or `mechanical`, with a pass threshold of two of three trials.
- Decision 13: exit non-zero only when the instrument could not run. The issue says this is "taken verbatim from the held-out suite's `check.mjs` contract" (A2 below).
- Decision 14: a cohort row per trial (agent model, judge model, Host harness version, `mh` commit, config digest, arm, trial index, start instant, duration, turn count).
- Decision 16: the live half never enters `verify`, `verify:commit` or `ci.yml`; "the product runs no model; the repository's tooling asks the Operator's Host harness to".
- Decision 19: first suite is a cut of the integrated tier config with three cases, two arms, three trials: 18 agent sessions and 18 judge calls per run.

What #222 differs from the brief on: it uses an LLM judge (Decision 10, 11) where the brief wants deterministic regex grading with a low-prior marker; it has no marker design at all; and it names no endpoint provider. Issue #222 carries label `ready-for-agent` and is open. It was never built. Nothing in it was measured; it is a spec, so none of its numbers (18 sessions, two of three) are measurements.

## A2. The retired ablation study (map #18, closed as won't do)

Map #18 designed a 3x2 experiment (governed, checks-only and bare arms; Sonnet 5 in Claude Code and Gemini 3.8 Flash high in Antigravity) to find which provisional records change what agents build. It was cancelled on 2026-09-08 (#18 comment 5586976663, "Closed as won't do"). The cancellation reason recorded is only "the adr-ablation experiment is cancelled"; no finding was recorded as the cause. The `prepare-ablation-run` skill was kept "to harvest later" and sits at `.agents/skills/prepare-ablation-run/`.

What ran: four runs completed before 2026-09-04 (`b3ff0fa` body and `methodology.md` both say so), and eleven runs had been minted when `--harness` became mandatory (methodology, "Metrics"). All four completed runs reached the frozen verdict `24/15/22` (`governedFiles` / `invalidFiles` / `totalViolations`) with all 18 violation codes reached. No cost figure was ever recorded as a measurement; methodology says cost "is computed, not read".

What went wrong, and what each failure taught. These are the lessons #222 says were "written down and then deleted", and they are the main prior art:

1. **The frozen gate saturated.** Four runs, one number. Commit `b3ff0fa`: "Layer 1 discriminates nothing... leaving it resting on a layer that is arm-favouring by construction." A deterministic expected-output gate that every arm passes carries no signal.
2. **The agents diverged on what the spec left open.** After the four runs, fourteen behaviours (commit `125e963`, `b3ff0fa`; `methodology.md` says "ten", a discrepancy inside the draft) were answered differently by different runs and all were volunteered in each run's `RESULTS.md` under "where the spec ran out". The fix was to define them in the spec so they could be scored. Lesson: a delegated behaviour cannot be scored.
3. **A held-out suite was the answer to a suite an agent can read.** `docs/evals/ablation/held-out/` (deleted) held 14 edges as `check.mjs`; `copy_kit` stamped only `kit/fixtures` and `kit/tests` into a run, so the directory was "out of reach of every arm by construction rather than by care". Its README: "A test a run can read is a test it can satisfy without understanding, which measures transcription rather than comprehension." Scored against the four runs it returned **6, 7, 8 and 12 of 14**, and each failure traced to a divergence the run's own report described.
4. **The first version of the held-out suite scored 3 of 14 for all four runs, and was wrong.** The config selectors carried a `corpus/` prefix while selectors match root-relative paths, so nothing was governed, every observation read "none", and "the table looked like a devastating result" (`b3ff0fa`). A total failure from an instrument that governs nothing is indistinguishable from a real result unless something tests the instrument.
5. **Instrument failure is not a score.** `check.mjs` tabulated edge failures and exited 0; a non-zero exit meant "no resolvable `bin.mh`, or no JSON where the spec promises some". `run.sh` exits 2 on misuse because `${1:?}` would exit 1 and collide with an ordinary shell failure (`b3ff0fa`, `run.sh`).
6. **Telemetry taken inside the session was partial and changed the measurement.** The first four runs had a `metrics.sh` stamped into the tree that the agent ran as its last act. Every figure excluded commits and report text written afterwards; one run appended telemetry and never committed it (`RESULTS.md` at 138 lines in git against 278 on disk) while another committed afterwards (227 lines counted). "Churn is therefore not comparable across those four runs at all" (`bc3e7a7`, methodology). The rule that followed: measure after the session, operator-side, never write back, because telling a run its record reads are counted "is the one measurement that changes what it measures".
7. **A commit is not a cohort key.** Runs minted on 2026-09-03 fell into two cohorts: the governed arm at `2745cf4` and at `40e43a2` differ by 74 insertions and 188 deletions across four records and an enforcer, because record edits landed between the mints. Both reported clean and nothing in either tree distinguished them (`225d9ec`). One run's `source_sha` resolved to `fatal: bad object` after an amend. The replacement was `scaffold_sha`, a content hash of the whole minted tree with symlinks hashed by target (`bc3e7a7`).
8. **A spec pinned by sha but copied from the working file.** `scaffold-design.md` pinned the spec at `ff5bc66`; the spec was amended by `125e963`; `stamp.sh` ran `cp` on the working file, so runs before and after the amendment received different specs (#18 comment 5540442482).
9. **A default of `unknown` poisoned the data.** `--harness` defaulted to `unknown`, and all eleven runs minted before it was made required recorded `unknown`; an unmetered harness and an unparsed transcript then looked identical (`bc3e7a7`, methodology "Metrics").
10. **The treatment leaked through the working directory.** Host harnesses stamp the cwd into context every turn. Run ids were changed to carry no treatment (`b1df3af` accepted a named cost: a slug and variant in the run id), and then the slug was changed to `mh` because `adr-ablation` "named both the subject under test and the fact that a study exists" (`967f6aa`).
11. **A leak sweep fired on nothing.** `sed "s|$RUN_ID||g"` became a no-op whenever the id held a regex metacharacter: `|` closes the command, sed exits 1, grep reads an empty stream, and the sweep prints "clean" over a tree it never opened (`b1df3af`). The repair was a two-sided canary and a `--model` held to `[a-z0-9-]`. Widening the sweep from `AGENTS.md` to the whole tree then found a real leak: governed's `vitest.config.ts` carried a comment explaining the experiment to its subject (`967f6aa`).
12. **A refusal that did not refuse.** `eval "$(preflight.sh)"` captured stdout while the refusal went to stderr, and `eval` of an empty string succeeds, so a refused mint went on to build a partial run that `verify-run` read as real (`3e7c4d4`). "That is exactly how a guard fails open -- it is only ever reached on the day it matters." Verification trap 15 is the general form.
13. **Derived configs came out prettier-dirty.** `strip-governance.py` edited config text without reformatting, so every non-bare run opened red on two files it never authored; the same script dropped `.archgate` entries and the governed arm opened on 38 eslint errors in files it could not touch, which "pointed its attention straight at the record layer through the error channel" (`967f6aa`). "A forced violation is a fixture defect, not a record that failed to bind."
14. **The bare arm's skill carried a clause that manufactured the thing being absent.** The `tdd` skill's "and respect ADRs in the area you're touching" was stripped in all arms because an agent told to respect ADRs and finding none "may hunt for or author its own governance, manufacturing the behaviour that arm exists to measure the absence of" (methodology, "Authoring skills"; draft-grade).
15. **A manipulation check needs a transcript.** Map #18's "Telemetry" row: dropping headless `-p` meant the question "did this run ever open a record?" survives only in the Host harness's transcript, so "a harness that cannot produce a readable transcript is not eligible to run the governed condition. Without that evidence a null is uninterpretable — it cannot separate the records don't bind from the records were never read." Commit `b1df3af` built record-channel telemetry (which records were opened by Read or by Bash, and how far into the session), recoverable from the transcript with no logging switched on.
16. **Runs are manual and interactive; headless was dropped.** The map's decision: every run "a manually launched interactive harness session"; "nothing is scripted AFK and nothing is a one-off `-p` invocation" (#18 body, Runs row). This is the opposite of #222 Decision 10 ("spawns the Host harness headless"). The draft methodology's headless flags (`--dangerously-skip-permissions`, `--setting-sources project,local`, `--strict-mcp-config --mcp-config '{}'`) were for the earlier headless design and are draft-grade; they are the only record of how the repository once isolated a Claude Code run from the user's own hooks and settings, and they were never verified in this note.

# Part B: repo-side constraints

## B1. Tenet 3 and the "run a model or hold an API key" boundary

- Tenet 3 (`docs/vision/architecture.md:52-57`): "No network, no model, no external service, no git call. The same tree in gives the same result out." It binds **the check path**. The decision procedure at `architecture.md:28-29` makes it a stop: "A 'no' on 3 or 4 is a stop, not a trade-off", and question 4 asks whether a change "make[s] the check path non-hermetic".
- The boundary row (`docs/vision/product.md:122`): the product does not "Run a model or hold an API key"; it "Delegates judgment to the host harness, on the user's own auth and bill". Row 125 adds the product does not "Act as a host harness". `product.md:118` states "Moving a boundary is a vision change."
- **Ruling on the text.** Both rows are written about "the product". Design-ADR 0004 bounds what the product is: the tarball is `dist/` only (`package.json:31-33`, `"files": ["dist"]`). A key held by repository tooling that is not in `dist/` and is not reached from `cli.ts` does not make the product hold a key, which is the reading #222 Decision 16 relies on ("the product runs no model; the repository's tooling asks the Operator's Host harness to"). Under that reading a `.env`-keyed endpoint provider is **not forbidden by the text**, with three conditions that make the reading hold: the runner and any key reading must be absent from `dist/` (the conformance Package is kept out by `tsconfig.build.json:40-47`; a new Package would need the same exclusion), it must be unreachable from `src/packages/cli/cli.ts`, and it must never enter `verify` or `ci.yml` (tenet 3 plus trap 13).
- **Where it strains.** (a) The row's "instead" clause names the Host harness as the place judgment is delegated, "on the user's own auth". An endpoint provider bypasses the Host harness entirely. (b) A bare endpoint needs a tool loop to write files; R4 calls it a "stand-in host", and the product row 125 says the product does not "Act as a host harness". As repository tooling that is not the product, so the row is not breached, but the eval then measures a surface no adopter uses. (c) The dogfood proof obligation (`docs/vision/product.md:112`: "this product runs against its author's own LLM-wiki continuously") blurs the line between this repository and the product, and a reviewer reading the vision doc cold could reasonably say the repository is the product's author-side deployment. The text does not settle (c); it needs a human sentence, and that sentence belongs in a design-ADR (altitude: a future feature could falsify it, so not an Archgate ADR).
- **`.env` facts, measured.** The checkout root holds a `.env` of 103 bytes with one variable name, `GH_TOKEN` (value not read), gitignored by `.gitignore:2`. Nothing in the repository loads `.env`: `grep` finds `process.env` only at `.agents/skills/markdown-harness/scripts/activity-log.mjs:82` (a named lookup) and `init.mjs:189` (`CLAUDECODE`). The `.env` is per checkout, so this worktree has none, and any runner reading it must treat absence as an instrument failure and never silently skip. The key present is a GitHub token for `gh`, not a model key; no model key is held by the repository today. A provider key would be the first.

## B2. Verification traps that bind a runner

All from `docs/agents/verification.md`; each trap's number is cited from elsewhere, so none may be renumbered.

- **Trap 2 (lines 30-46), worktrees.** `verify` is unmeasured inside an agent worktree until `npm ci` is run there; measured 2026-09-04 in a `.worktrees/` worktree, `npm ci` took `node_modules/.bin` from absent to 32 entries and `verify` to exit 0. Concretely for an eval runner: it will be developed in worktrees, so its own tests inherit the same contamination; and its mint step must not copy or link the worktree's incomplete `node_modules`. A runner that mints roots from a worktree's `dist/` is measuring that worktree's build.
- **Trap 9 (lines 150-160), process-boundary suites spawn `dist/`.** `bin.mh` is a compiled artefact and the suite's start-up guard only checks that `dist/` exists, never that it is current. For the eval: the deterministic half's runner (spawns `mh`) and the live runner both measure whatever `dist/` holds. The runner must either build first or record a content digest of the `dist/` it used in the cohort row. #222's "`mh` commit" does not name the bytes that ran; the commit can be ahead of `dist/`.
- **Trap 10 (lines 162-186), a hook reported `wired` is not one that will run.** Two measured reasons: the Host harness watcher can miss a settings write, and a `Read` or `Write` matcher never sees `Bash cat`/`tee`/heredoc creation. For the eval this means a steered arm in which the hook never fired is a null that looks like "intent inert". The guard the repository already has is `docs/markdown-harness/activity.csv`, which `assess-hook.mjs` appends to on every invocation that finds a config root (silent ones included). `query-hook.mjs` does not write that row (#221 comment 5980948131: "I did not give it the activity-log row"), so today a steer trial cannot prove its hook ran. The eval needs a per-trial proof, from a log or a transcript, that the hook delivered. This is the manipulation check of A2 item 15.
- **Trap 13 (lines 239-256), `ci.yml` duplicates `verify`.** `.github/workflows/ci.yml` lists nine steps (`archgate`, `markdown-harness`, `eslint`, `prettier`, `tsc`, `boundaries`, `build`, `vitest`, `knip`) and does not call `npm run verify`. A deterministic half appended to `verify` alone runs only on a tag; to run on a PR it needs a CI step too. Inversely, a live script wired into neither is safe by construction. Note that the deterministic half needs no new gate step if it is a vitest test file: `vitest run` is in both chains and its `include` is the greedy `**/*.{test,spec}.ts` (`vitest.config.ts:5`).
- **Trap 14 (lines 258-300), reads come back short.** A whole-file read can silently lose content; read in windows of 30 lines or fewer and anchor edits. Concretely for the runner: (a) it reads a model-produced file and a config, and must verify the byte length and a hash against what the session wrote; (b) the judge sees a file excerpt, so truncation of the file the judge reads would be scored as a rubric failure; (c) the same trap applies to the agent under test, so a short read of the template is a confound. The runner's own numbers (counts, sizes) must come from a program that writes its answer, not from terminal output.
- **Trap 4 (line 55), counts from evaluating arrays.** Applies to two-way closure (#222 Decision 6).
- **Trap 7 (line 103), `prettier --write .` bricks content-pinned trees.** Deliberately defective repair seeds, and the intent-neutralised derived configs if committed, need `.prettierignore` entries scoped to the directory (as `fixtures/conformance/body-structure/**` is). `prettier --check .` runs inside `verify` over everything not ignored.
- **Trap 11 (line 188), `.agents/skills/` is reached only by `prettier`.** The same holds for any script outside `src/`: `archgate` has no ADR in scope and `eslint` configures no rule for it. A live runner placed there is ungoverned.
- **Trap 15 (lines 303-330), a refusal upstream can leave a guard unreachable.** For the eval: a transcription guard or a closure check whose bad case the mint refuses to produce passes forever. Each guard needs its bad case constructible at the level the guard sits.
- **Trap 1 (line 23), `archgate check` is changed-files-scoped.** A new Archgate ADR whose `files:` glob matches nothing changed reports `total: 0`.

## B3. `fixtures/conformance/**` is out of scope, and why

- **Why.** `ARCH-002-conformance-suite.md:7-8` scopes the record to `fixtures/conformance/**` and Decision 1.1 says "This record's scope MUST stay `fixtures/conformance/**`, never `fixtures/**`". `ARCH-010` has the same glob. The Conformance suite is "the contract for what `markdown-harness` must report" (`CONTEXT.md:427-436`); Conformance cases are "specification and not test data" (#221 comment) and changing or removing one is a contract change (ARCH-002 §3.2-3.3 as quoted by #1's audit). The vision doc says the corpus "is declared a specification" (`architecture.md:176-183`) and that a change to its expected reports "is a contract change".
- **Consequences for the eval.** The eval suite must not edit, move or add to any file under `fixtures/conformance/**`, because that would be a contract change by someone measuring behaviour. It also must not **depend** on it by path: the integrated tier's config is the intended seed (#222 Decision 19), and copying bytes from it makes the eval's config a snapshot that drifts silently when a Conformance case moves (the closure rule in ARCH-002 §1.4 grows the corpus with the vocabulary). The eval root should copy once, state the Conformance commit it was cut from, and prove it still loads; it must not import a tier path at run time. `ARCH-002-conformance-suite.rules.ts:28` pins the case glob `fixtures/conformance/*/docs/**/*.md`, so anything an eval adds under `fixtures/conformance/` would be swept in as a case and need an `expect` marker.
- **Related.** `fixtures/llm-wiki/` is reserved (ARCH-002 §1.3) as a separate synthetic root for a freely editable demo tree; it does not exist. `fixtures/evals/` is outside both ADR globs, so nothing governs it today (#222 Decision 18). `CONTEXT.md` defines a "corpus" as an adopter's own tree and "fixture" as "ordinary test data anywhere in the repo that pins nothing"; an eval suite root is a synthetic repo root, and its cases pin expectations, which conflicts with the "fixture" definition (see Glossary gaps).

## B4. Layout: a new Package, versus a non-Package `evals/` directory

**What a Package would look like** (`ARCH-004-folders-and-files.md:46-51`, example at lines 20-43; `src/packages/AGENTS.md`):

- A flat directory `src/packages/<name>/` whose root files are kebab-case with no suffix and are the only public surface; everything below carries exactly one classifier (`.pure`, `.impure`, `.types`, `.test`); integration tests under `tests/`; unit tests beside a same-name `.pure.ts`. The closest precedent is `src/packages/conformance/` (root entry points `tier-record.ts`, `tier-enrolment.ts`, `case-corpus.ts`; `lib/` subfolders; `tests/*-tier.test.ts` runners).
- It must not be a Module (`ARCH-009:27` says so for the conformance Package, and `ARCH-008` §1.4 says only `cli` composes Modules), so it must not import `frontmatter-harness` or `body-structure-harness`, and no Module may import it. It may import `foundation` and `config-contract` entry points, and tests may spawn the compiled `mh`.
- It must be excluded from the build like conformance: `tsconfig.build.json:46-47` excludes `src/packages/conformance/**` because "an adopter installing the tarball receives a bin and nothing else". A new Package needs the same line, or it ships in `dist/` (design-ADR 0004 measured the tarball falling from 417 files to 59 by bounding it; `files: ["dist"]` alone does not exclude it because `dist/` is the build output).
- `knip.json:3` lists only `.archgate/adrs/*.rules.ts` and `src/packages/cli/cli.ts` as entries, and `project` is `src/**/*.ts`. A Package reached only by its own tests is covered by knip's test-file entries, but an executable entry (a runner script that nothing imports) would be reported as an unused file unless added to `entry`.
- `vitest.config.ts:5` includes `**/*.{test,spec}.ts` greedily, and excludes `.worktrees/**`, `.claude/worktrees/**` and the vendored ablation assets. Any `*.test.ts` committed under `fixtures/evals/**` (a seed overlay, say) would be run by `verify`; add an `exclude` or avoid the name.

**The collision that decides placement: `ARCH-008` §2.1** (`.archgate/adrs/ARCH-008-module-boundaries.md:32`): "Only `foundation` MAY import a platform builtin; every other Package MUST reach the filesystem through it." Enforced by `only-the-gate-imports-a-builtin` (`.dependency-cruiser.cjs:153-159`, `from` any file under `src/packages/` except `foundation` and the two test homes, `to` any `core` dependency type). `child_process` appears under `src/` only in test files (`cli/tests/assess-hook.test.ts`, `query-hook.test.ts`, `cli.test.ts`, `conformance/tests/body-structure-tier.test.ts`, `integrated-tier.test.ts`) and in skill scripts. `foundation` imports only `node:fs`, `node:path`, `node:url` (`foundation/lib/platform/node-host.impure.ts:23-25`). So a Package `.impure.ts` file that spawns a Host harness, creates a temporary root, copies a build or writes a report cannot pass `lint:boundaries`. Three exits exist: (1) add spawn, temp-directory creation and copy to `foundation/lib/platform/` (the text allows it, but it puts a process-spawn capability into the Package that carries tenet 3 for the hermetic check path and ships in `dist/`); (2) amend ARCH-008 (`ARCH-004:113`: "Exceptions: raise a separate ADR; human approval required"); (3) keep the impure seams outside `src/` and keep only pure logic in a Package. Option (3) is the only one that touches no existing record.

**Where a non-Package directory sits.** Candidates are `fixtures/evals/` for suite roots (as #222 says), and the runner as scripts beside them or in a skill directory. What each gets:

| Location                                                                                                          | prettier | eslint                               | tsc                                             | knip                            | archgate        | depcruise                     | vitest                     |
| ----------------------------------------------------------------------------------------------------------------- | -------- | ------------------------------------ | ----------------------------------------------- | ------------------------------- | --------------- | ----------------------------- | -------------------------- |
| `.agents/skills/<skill>/scripts/*.mjs` (precedent: `query-hook.mjs`, `setup-local-e2e-repo/scripts/new-repo.mjs`) | checked  | parsed, no rule configured (trap 11) | not included                                    | not in `project`                | no ADR in scope | not scanned (`depcruise src`) | tests found by greedy glob |

Because `eslint.config.mjs:30` sets `GOVERNED` to `src/**/*.ts` and the exhaustiveness net at `eslint.config.mjs:473-488` fires only there, a `.ts` runner outside `src/` is invisible to the layout regime: no classifier suffixes and no purity enforcement. If the pure logic (neutralising, closure, classification, cohort, guard) goes into a Package it inherits ARCH-003, 006, 007 and the boundaries rules; the `.mjs` or `.ts` outside imports only its entry points, which depcruise's `entrypoint-boundary-from-app` allows (`.dependency-cruiser.cjs:77-82`, "App/root code may import a package's entry points"). Running TypeScript from an outside script relies on Node's type stripping (`#1` comment 5590259014 shows `node src/packages/cli/cli.ts` running directly); that is repository tooling practice and not a documented contract.

## B5. Archgate ADRs that bind (`archgate adr list`, `archgate adr show`)

Fifteen records exist (`archgate adr list`). Read in full for this note: ARCH-001, 002, 003, 004, 006, 007, 008, 009 (decisions), plus the `files:` globs of 010, 011, 012 and GEN-003. Summary of Do/Don't that bind an eval runner:

- **ARCH-003 Testing** (`files: ['src/**/*']` for the test Disciplines; the record text is in `.archgate/adrs/ARCH-003-testing.md`). Decision 1: tests are fully deterministic with "zero dependence on ambient state or network"; no `vi.mock`, `vi.spyOn`, snapshots, `.skip`, assertion-free bodies. Decision 2: three top-level `describe` blocks (`success cases`, `failure cases`, `edge cases`). Decision 3: `// ARRANGE`, `// ACT`, `// ASSERT` markers; no magic strings in `// ASSERT`. Decision 4: two homes (`<pkg>/tests/*.test.ts` through entry points; `<pkg>/<subfolder>/*.test.ts` beside a same-name `.pure.ts`). **Do:** write tests for the deterministic half and the pure parts with hand-written stand-ins. **Don't:** write a test that calls a model, a clock, a network or an unpinned instant; do not mock the spawn. ARCH-003 forbids mocks; it does not say a spawn is untested. #222 says the spawns are "not tested" and attributes it to ARCH-003, which is a choice and not a record's text; an `.impure.ts` is exercised "through the entry point" at `tests/` (ARCH-003 §4.1).
- **ARCH-004 Folders and Files** (line 46): every source file under `src/` sits in a Package. **Do:** root entry points kebab-case, no suffix. **Don't:** stray files at `src/packages/`, a file called `utils`, `helpers`, `common` or `misc`, or a `.orchestrator` or `.adapter` suffix (ARCH-004 §4). Name a file for its subject: `rubric-closure.pure.ts`, not `runner-helpers`.
- **ARCH-006 The pure Classifier** (the pure record bans the ambient reads; the import hole of line 76 is narrowed by two `.dependency-cruiser.cjs` rules, and ARCH-007:42 says an extracted deterministic function "MUST NOT reach a platform builtin"): no `Date.now`, `Math.random`, `performance.now`, zero-argument `Date`, local-time accessors, locale formatters; no mutation of arguments. **Do:** pass the instant, the model name, the trial index and the digest in as arguments. `.env` parsing is therefore a hand-written pure parser over a string or an impure file, never `util.parseEnv` in a pure file (R4 makes the same point).
- **ARCH-007 The impure Classifier** (`ARCH-007:22`): membership by exclusion, last resort; impure-pure-impure sandwich, effects at the edges; extract deterministic logic into a `.pure` file that receives its data as arguments and does not import its origin; **"a conditional MUST NOT encode a business rule"**. For the runner: the decision "is this an instrument failure or a graded failure?" must be a pure function over data (exit status, parse result, file presence) whose answer the impure shell turns into an exit code.
- **ARCH-008 Module Boundaries** (§2.1 above, and §1): the platform gate. Also §3 and §4: only `cli` composes. **Don't** let the eval Package import a Module or name a Module's section types, which matters because the neutralising function needs to find `intent` carriers in a config that two different Modules define. A carrier walk that names `body-structure`'s `headings` shape imports a Module's types and breaks §1.4. The neutraliser has to work from the loaded config through `foundation`/`config-contract` vocabulary or by reading the YAML document generically, and the two-way closure needs an enumeration of carriers per Module that no Package outside the Module may name. This is an unresolved design problem, not a detail (see decisions).
- **ARCH-009 / 010 / 011** govern the Conformance Package and corpus only (`files:` globs `src/packages/conformance/**` and `fixtures/conformance/**`). They do not bind an eval Package, but they are the template: one record per tier, tier enrolment comparing fixture directories with runner names in both directions, a pinned assessment instant ("An unpinned suite MUST be treated as non-existent, not passing", ARCH-009 §3.2). An eval Package that mirrors enrolment gets that guarantee by copying a pattern, not by inheriting a rule.
- **ARCH-012 Module-free contracts** (`config-contract/**`, `response-contract/**`): no Module names there. Do not add eval vocabulary to either.
- **ARCH-001 Dependency admission** (`ARCH-001:22-25`): a new dependency needs the four-signal screen and a `~x.y.z` or exact range. The runner should add none: Node ships `parseEnv`, `fetch`, `child_process`; `yaml` and `marked` are already dependencies.
- **GEN-003** (`src/**/*`): no inline eslint suppression. A runner cannot silence the `only-the-gate-imports-a-builtin` boundary with a comment.
- **ARCH-002** applies only to `fixtures/conformance/**`. #222 Decision 18 asks for a new record covering `fixtures/evals/**`; per `docs/agents/domain.md` and `CLAUDE.md`, Archgate records are created and edited only through `archgate:adr-author`, and the altitude test ("If the next feature could make the record wrong, it was written at the wrong altitude") means a new ADR must state only what any future eval would keep.

# Glossary gaps

`CONTEXT.md` has no entry for any of the following, and several need one before spec agents use them. Each is "needed by the spec", with a note on where existing terms collide.

- **eval suite, eval case, case kind (steer, repair, assess), arm, trial.** Collisions: `CONTEXT.md` defines the **Conformance suite** and says "The whole is the suite; the per-tier unit is a **corpus tier**, never 'a suite'" and lists "test suite" under _Avoid_. An "eval suite" under `fixtures/evals/<suite>/` uses "suite" for a per-root unit, which is the exact usage the entry forbids for tiers. Pick a different noun (R-series may already). `arm` was a glossary term for the retired ablation and was removed from `CONTEXT.md` by `a425162`; reintroducing it reopens a retired word.
- **intent carrier, intent address.** `CONTEXT.md` mentions `intent` in the Rule entry (`CONTEXT.md:267`, "a mandatory `intent`") and says it is "the Operator's verbatim `intent`, never a sentence this repo wrote" (`CONTEXT.md:100`), but has no entry for what an `intent` is, nor for the five places it sits (Rule, `pattern` sibling, `allowed[]`, spine entry, `assess.stale`). `fault.types.ts:101-103` names two faults for it. A carrier list belongs where the Modules declare it; the glossary should define the word and point at it.
- **steering signal.** The brief uses it. `CONTEXT.md` defines **Steering query** ("Asking the config what governs a path **before** the file is written") and uses "Steering content" for what `--query` returns, plus **Signal** at `CONTEXT.md:401`, defined as "What a document states about its own trustworthiness, in the file" (provenance, trust tier, freshness, lifecycle), with _Avoid_: warning, status, health, score. "Steering signal" collides with that entry, because the brief means the Operator's words reaching an agent, and a Signal is a property of a file. Use "Steering content" or define the new term.
- **Level one**, as in "does the signal reach the agent and change what it writes". No glossary entry and no definition of the other levels. The spec agents should state what level two is, or drop the numbering.
- **marker, low-prior marker, cohort row, instrument failure, graded failure, held out.** "Marker" collides with ARCH-002's `<!-- expect: VERDICT -->` and `<!-- assess: ACTION -->` markers, which are HTML comments in Conformance cases and unrelated to the eval's behavioural marker. "Held out" and "held-out suite" were glossed in the deleted ablation README only. "Cohort" is not in `CONTEXT.md`.
- **provider, stand-in host, delivery channel** (R4's provisional terms). "Provider" has no existing meaning in `CONTEXT.md` and is safe; "stand-in host" sits near the **Host harness** entry (_Avoid_: "agent host, agent runtime, wrapper") and must always be qualified.
- **runner.** `ARCH-009` uses "runner" for one `<tier>-tier.test.ts`. An eval "live runner" is a different thing; qualify it.
- **The brief's "harness".** `CLAUDE.md` says bare "harness" is ambiguous and must be qualified: write `markdown-harness` for the product and Host harness for the agentic CLI.

# What spec agents must decide

1. **Where the impure seams live.** `ARCH-008` §2.1 puts spawn, temp-directory creation, file copy and report writing outside any Package. Either keep the runner outside `src/` with pure logic in a Package (the only option that edits no record), or spend an amendment to ARCH-008 through `archgate:adr-author` with human approval. Name which, and name the knip `entry`, `tsconfig.build.json` exclusion and `.prettierignore`, `vitest` `exclude` and `ci.yml` changes it needs.
2. **Whether an `.env`-keyed endpoint provider is in this round.** If yes, write the sentence that reads `product.md:122` as binding the shipped product only, state that no key-reading file is reachable from `cli.ts` or present in `dist/`, and say what the runner does on an absent `.env` (instrument failure, exit non-zero). If the Operator wants the boundary untouched, restrict to Host-harness providers as #222 Decision 16 did.
3. **What a steer case measures given a `PreToolUse` hook.** #221's write-up says the hook's `additionalContext` arrives after the first draft is composed. Decide whether the graded artifact is the first write, the final file after the agent has seen the hook output, or a deny-first variant, and whether a Bash-created file counts. This decides the meaning of "steered arm".
4. **The manipulation check.** What proves in each trial that the steering signal was delivered (an `activity.csv` row, which `query-hook.mjs` does not write; a transcript record; a hook-emitted marker the grader reads)? A delivery that did not happen must be an instrument failure, not an `inert` outcome (A2 item 15; trap 10).
5. **Instrument failure versus graded failure, exactly.** List every case that exits non-zero (no `dist/`, no Host harness binary, no model key, no parseable session output, hook never delivered, mint refused) and every case that tabulates and exits 0. Follow `docs/design-adr/0003-response-envelope-and-config-filename.md` for vocabulary and A2 items 5 and 12 for the failure-open guard.

13. **Statistical floor.** There is no prior measurement of the variance of these runs: the only data are four completed runs at one number. Decide the trial count, the threshold and the number of arms-by-trials from a stated budget, and record that nothing prior supports "two of three".
